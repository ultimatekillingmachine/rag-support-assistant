# Ассистент поддержки (Support RAG Assistant)

[English](README.md) · **Русский**

[![CI](https://github.com/ultimatekillingmachine/rag-support-assistant/actions/workflows/ci.yml/badge.svg)](https://github.com/ultimatekillingmachine/rag-support-assistant/actions/workflows/ci.yml)

Ассистент, который отвечает на вопросы покупателей **только по статьям базы знаний компании**, показывает, какие статьи использовал, и говорит «не знаю» вместо того, чтобы выдумывать.

Проект сделан как портфолио: он показывает весь путь AI-функции — от документов до работающего сервиса, причём качество здесь **измеряется**, а не заявляется на словах.

> **Демо-данные:** вымышленный магазин электроники «ТехноМаркет» и его статьи поддержки (29 статей, 8 разделов). Тексты специально на русском: большинство демо-проектов умеют работать только с английским, а российским компаниям важен именно русский язык.

## Какую задачу решает

- **Ответам можно доверять.** Бот поддержки не имеет права придумывать сроки доставки или правила возврата. Поэтому ассистент отвечает только по статьям базы знаний и всегда показывает источники.
- **Обычного поиска недостаточно.** Покупатель спрашивает своими словами («телефон упал, экран треснул — это гарантийный случай?»), а в статье написано «трещины, следы падения». Сервис понимает смысл, а не только точные слова.
- **Честность важнее догадок.** Если вопрос выходит за пределы базы знаний, ассистент прямо об этом говорит и предлагает передать вопрос человеку — вместо уверенного неправильного ответа.

## Как это работает

```
статьи базы знаний (knowledge_base/*.md)
      │  чтение + разбивка на маленькие кусочки
      ▼
числа, описывающие смысл ──► хранилище всех кусочков (SQLite для разработки │ Postgres для продакшена)
                                                             ▲
вопрос покупателя ──► поиск самых подходящих кусочков ───────┘
                      (поиск по смыслу │ + поиск по точным словам;
                       проверка уверенности; не более одного кусочка на статью)
                                                             │
                                                             ▼
                     «отвечай только по этим кусочкам» ──► AI-модель (любая OpenAI-совместимая │ Ollama │ офлайн-заглушка)
                                                             │
                                                             ▼
                              ответ + список источников + время ответа
```

## Что внутри и почему так

| Часть | Что выбрано | Почему |
|---|---|---|
| Веб-сервис | FastAPI | Быстрый, современный, сам создаёт документацию к своему API |
| Поиск по смыслу | `intfloat/multilingual-e5-large` (работает локально) | Хорошее качество на русском, не нужны платные API, данные не покидают компьютер |
| Хранилище | SQLite (разработка) / Postgres с pgvector (продакшен) | Работает сразу после скачивания; продакшен-путь подготовлен в `docker-compose.yml` |
| Поиск по точным словам | Собственная небольшая реализация BM25 | Не нужна лишняя зависимость; математика ранжирования остаётся читаемой и тестируемой |
| AI-модель | Любой OpenAI-совместимый адрес (DeepSeek, OpenAI, OpenRouter), локальная Ollama или офлайн-`mock` | Проект запускается и тестируется **без единого API-ключа** |
| Контроль качества | pytest, ruff и собственный скрипт оценки | Качество — это число, за которым можно следить, а не ощущение |

## Быстрый старт (работает без интернета и без API-ключа)

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt
copy .env.example .env            # по умолчанию: SQLite и офлайн-заглушка вместо AI
python -m scripts.ingest_kb       # прочитать статьи и подготовить поисковый индекс
uvicorn app.main:app --reload
```

Затем задайте вопрос (или откройте автоматическую страницу API: http://127.0.0.1:8000/docs):

```bash
curl -X POST http://127.0.0.1:8000/ask -H "Content-Type: application/json" -d "{\"question\": \"Сколько идёт доставка в регионы?\"}"
```

Или без запуска сервера:

```bash
python -m scripts.ask_cli "Сколько идёт доставка в регионы?"
```

На вопросы вне базы знаний (например, «В каком году основан ТехноМаркет?») приходит честный ответ «нет информации», а не выдуманный.

### Подключение настоящей AI-модели

Достаточно изменить строки в `.env`:

```ini
# DeepSeek
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-...            # ваш ключ
LLM_MODEL=deepseek-chat

# или модель, работающая на вашем компьютере (Ollama)
# LLM_BASE_URL=http://localhost:11434/v1
# LLM_MODEL=qwen2.5:7b
```

Всё остальное остаётся прежним: сервис, поиск, оценка качества.

```bash
python -m scripts.run_eval      # сравнивает режимы поиска, показывает hit@1/3/5 и MRR
```

Набор для проверки — 56 вопросов, написанных вручную: у 51 есть известная
правильная статья, а 5 специально **выходят за пределы** базы знаний.

Результат на настройках по умолчанию (`intfloat/multilingual-e5-large`, 5 кусочков в ответе):

| Показатель | Результат | Пояснение |
|---|---|---|
| hit@3 | **1.000** | Правильная статья попадает в топ-3 **для каждого** вопроса |
| hit@1 | 0.941 | Правильная статья стоит первой для 48 вопросов из 51 |
| MRR | 0.971 | В среднем правильная статья оказывается почти на самом верху |
| вопросы вне базы | 2 из 5 отсеяны | Проверка уверенности ловит часть «вопросов-ловушек» |
| неверные отказы | **0 из 51** | Ни один настоящий вопрос не был ошибочно отклонён |

Эти числа получены командой `python -m scripts.run_eval` и воспроизводятся на любом компьютере.

### Почему настройки именно такие

1. **Добавление поиска по словам сначала ухудшило результат** (hit@1 упал с 0.958 до 0.854). Причина: поиск по точным словам без учёта русских форм слов («треснул» и «трещины») поднимал наверх *неправильную* статью. Это известная слабость простого подхода.
2. **Больший вес поиска по смыслу** (и меньший — поиску по словам) вернул объединённый режим к hit@1 = 0.941 — на уровне поиска по смыслу.
3. **Ограничение «один кусочек на статью»** решило другую проблему: раньше одна длинная статья занимала 4 из 5 мест и вытесняла правильную статью.
4. **Решение:** по умолчанию используется поиск по смыслу + проверка уверенности. Объединённый режим доступен как готовая опция для случаев, где важнее точные термины (коды товаров, названия моделей), или когда используется более лёгкая модель поиска.

### Как выбирался порог уверенности

Лучшее значение лежит между худшим «хорошим» вопросом (0.802) и лучшим
вопросом вне базы (0.830), но эти группы пересекаются — идеального числа нет.
Выбранное значение (0.80) никогда не отклоняет настоящий вопрос и отсеивает
часть «ловушек». Отклонённые вопросы вообще не отправляются в AI-модель, то
есть не стоят денег. Это осознанный выбор: в поддержке неправильный ответ
хуже, чем уточняющий вопрос.

## Если что-то не работает

**Windows: ошибка `ONNXRuntimeError: External data path escapes model directory`**

Windows может хранить скачанные AI-модели как ярлыки (симлинки), ведущие
наружу из папки модели, и локальный движок отказывается их загружать. Проект
сам выставляет `HF_HUB_DISABLE_SYMLINKS=1`, поэтому на новую загрузку это не
влияет. Если ошибка уже возникла — удалите скачанный кэш и пересоберите индекс:

```powershell
Remove-Item "$env:TEMP\fastembed_cache" -Recurse -Force
python -m scripts.ingest_kb
```

**При первом запуске скачивается модель поиска** (~2.25 ГБ для `intfloat/multilingual-e5-large`).
Она кэшируется и используется дальше. Для лёгкого варианта укажите
`EMBEDDING_MODEL=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (~0.5 ГБ).
