# Support RAG Assistant

[![CI](https://github.com/ultimatekillingmachine/rag-support-assistant/actions/workflows/ci.yml/badge.svg)](https://github.com/ultimatekillingmachine/rag-support-assistant/actions/workflows/ci.yml)

[English](README.md) · **Русский**

Ассистент, который отвечает на вопросы покупателей **только по статьям базы знаний компании**, показывает использованные статьи и говорит «не знаю» вместо выдуманного ответа.

Работает офлайн сразу после установки: локальные эмбеддинги, SQLite и офлайн-заглушка вместо модели. Для настоящих ответов достаточно подключить любую OpenAI-совместимую модель (DeepSeek, OpenAI, локальную Ollama).

## Как это работает

```
статьи базы знаний ─► разбивка на кусочки ─► эмбеддинги ─► хранилище векторов
                                                                    ▲
вопрос ─► поиск (по смыслу │ + по словам, объединение через RRF) ───┘
       ─► проверка уверенности (ничего близкого ─► отказ)
       ─► промпт: «отвечай только по этим фрагментам» ─► LLM
       ─► ответ + нумерованные источники
```

## Возможности

| Область | Что реализовано |
|---|---|
| Поиск | по смыслу; дополнительно по словам (BM25) с объединением; порог уверенности; не более одного кусочка на статью |
| Ответы | только по найденным фрагментам, нумерованные ссылки на источники, честный отказ |
| Диалог | уточняющие вопросы решаются с учётом предыдущей реплики |
| Потоковая выдача | `POST /ask/stream` (server-sent events) и небольшая страница чата |
| Права доступа | токены; внутренние статьи невидимы покупателю |
| Производительность | кэш ответов, перцентили задержки в `GET /stats` |
| Индексация | инкрементальное обновление (хеши содержимого и настроек, миграция схемы) |
| Развёртывание | `Dockerfile` и `docker-compose.yml` (приложение + Postgres/pgvector) |

## Быстрый старт

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows (иначе: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env            # по умолчанию: SQLite и офлайн-заглушка
python -m scripts.ingest_kb       # построить поисковый индекс
uvicorn app.main:app --reload     # затем открыть http://127.0.0.1:8000
```

Страница чата попросит токен (по умолчанию `customer-token`). Пример обращения к API:

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Authorization: Bearer customer-token" \
  -H "Content-Type: application/json" \
  -d "{\"question\": \"Сколько идёт доставка в регионы?\"}"
```

## Настройки

Все параметры — в `.env` (полный список в `.env.example`):

| Переменная | По умолчанию | Значение |
|---|---|---|
| `EMBEDDING_MODEL` | `intfloat/multilingual-e5-large` | локальная модель эмбеддингов (~2.25 ГБ, кэшируется) |
| `LLM_PROVIDER` | `mock` | `mock`, `openai_compatible` или `ollama` |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | — | доступы к модели, которая пишет ответ |
| `STORAGE_BACKEND` | `sqlite` | `sqlite` (без настройки) или `postgres` (pgvector) |
| `API_TOKEN_CUSTOMER`, `API_TOKEN_OPERATOR` | примеры значений | токены доступа; сменить перед публикацией |
| `HYBRID_ENABLED` | `true` | добавлять поиск по словам к поиску по смыслу |
| `RERANK_ENABLED` | `false` | второй этап переранжирования (на этих данных медленнее и хуже) |
| `MIN_RELEVANCE_SCORE` | `0.80` | ниже этого значения ассистент отказывается отвечать |
| `CACHE_ENABLED`, `CACHE_TTL_SECONDS` | `true`, `900` | кэш ответов |

## API

| Эндпоинт | Авторизация | Назначение |
|---|---|---|
| `GET /health` | — | работоспособность и размер индекса |
| `GET /stats` | — | доля попаданий в кэш и перцентили задержки |
| `POST /ask` | токен | один обоснованный ответ (JSON) |
| `POST /ask/stream` | токен | то же самое потоком (server-sent events) |
| `GET /` | — | страница чата |
| `GET /docs` | — | автоматическая документация API |

Тело `POST /ask`: `{"question": "...", "top_k": 5, "history": [{"role": "user", "content": "..."}]}`.
`history` необязателен и ограничен 12 сообщениями; роль берётся из токена, а не из тела запроса.

Каждый источник содержит `slug`, `title`, `category`, `updated_at` и `score` — близость к вопросу по шкале 0…1, одинаковой для всех режимов поиска (кусочки, найденные только по словам, получают 0.0).

## Качество

Набор для проверки — 56 вопросов, написанных вручную: 51 с ответом и 5 намеренно вне базы знаний.

```bash
python -m scripts.run_eval      # сравнение режимов поиска
python -m scripts.gate_report   # подбор порога уверенности
```

| Показатель | Результат |
|---|---|
| hit@3 / hit@5 | **1.000** |
| hit@1 | 0.941 |
| MRR | 0.971 |
| ошибочных отказов настоящим вопросам | **0 из 51** |

Измеренные решения — коротко:

* Гибридный поиск по словам вышел на уровень поиска по смыслу только после **стемминга русского**: без него формы «треснул»/«трещины» поднимали наверх не ту статью.
* **Кросс-энкодер** ухудшил порядок выдачи (hit@1 0.941 → 0.843) и работал в 50 раз дольше, поэтому выключен по умолчанию; порог, подобранный под одну модель оценки, не переносится на другую.
* Отказ **не вызывает модель вообще**, поэтому ничего не стоит.

## Обновление индекса

```bash
python -m scripts.ingest_kb          # инкрементально: только новые/изменённые статьи
python -m scripts.ingest_kb --full   # полная пересборка
```

| Сценарий (корпус 29 статей) | Переиндексировано | Время |
|---|---|---|
| Первая сборка | 29 статей | 202 с |
| Без изменений | **0** | **0.1 с** |
| Изменена одна статья | 1 | 15 с |

## Развёртывание

```bash
docker compose up -d          # приложение + Postgres с pgvector
python -m scripts.smoke_api http://127.0.0.1:8000   # сквозная проверка
```

`smoke_api` проверяет весь контракт: без токена → 401, покупатель видит только публичные статьи, оператор доходит до внутренних, стриминг отдаёт «источники → токены → завершение», страница чата доступна.

## Структура проекта

```
app/                код сервиса (статьи, поиск, промпт, API, страница чата)
knowledge_base/     статьи базы знаний (пример содержимого, 29 статей / 8 разделов)
data/eval/          56 размеченных вопросов
scripts/            индексация, вопрос, оценка, отчёт по порогу, смоук-тест
tests/              90 тестов; модель подменяется заглушками, поэтому CI работает без загрузок
```
